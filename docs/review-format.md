## 1. 文件职责与审核边界

- HTML为主要人工阅读、核对及导出界面；Python生成内容，CSS控制布局，内嵌JavaScript实现本页交互，无需后台服务。
- Markdown保留最后确认的ABC格式及原始审核载荷用途；HTML展示不等于已批准入库。
- 所有条目初始待审核。复选框仅用于临时筛选，不代表确认、否决或数据库审批。
- 导入仍需显式确认最终GPC及报价字段，通过现有受保护事务入口；页面操作不写业务数据库。
- 保留既有文件，不把旧版排版当作现行格式，也不因换样式重新调用BangumiAPI或DeepSeek。

## 2. 共用内容约定

识别顺序为别名库→本地BGM库→匿名BangumiAPI→DeepSeek辅助；任一阶段唯一命中即停止后续识别，多候选不算唯一命中。人工最终审核始终保留。

- 命中四槽顺序固定；候选不等于命中，不用DS选择冒充API命中。
- 名称后附Subject ID，链接指向`https://bgm.tv/subject/{id}`。没有Subject ID时不能补造。
- 默认内容版本为标准版（主版本），不因原文没有版本说明单独提示“版本待确认”；明确版本或真实关系歧义仍须核对。
- 默认报价平台PS5；原名明确PS4优先。选定候选平台清单支持PS4且未列PS5时当前实现显示PS4；缺失平台资料不当作不存在PS5的证据。不能拿未选定候选决定报价平台。
- 原文金额是最终报价，史低文字仅保留为证据备注；无优惠文字保存空字符串，不自动写“直接购买”。地区、日期、价格缺失以及API/AI失败仍须如实呈现。
- 可读表、候选建议与确认载荷分开；不能因视觉高亮或默认规则跳过审核。

## 3. HTML文件名、解析时刻与改版编号

页面主标题及浏览器标题：`《笔记标题》—— 解析MM/DD HH:mm`；同一解析内容第2版起追加全角`（2）`、`（3）`。

文件名：`人工核对表_YYYYMMDD_来源名_MMDDHHmm.html`；第2版起扩展名前追加半角`(2)`、`(3)`。

| 部分 | 规则 |
| --- | --- |
| YYYYMMDD | 出价日，不带“出价日”前缀或横线；页面出价日仍显示YYYY/MM/DD |
| 来源名 | 文件输入取文件名去扩展名；URL输入取笔记标题 |
| MMDDHHmm | 原始解析输出时刻，上海时区，改页面格式时保持不变 |
| 版号 | 新解析从第1版开始且不显示括号；同一批次改版递增，旧文件保留 |

当前第2版标题：`《11.3｜Ps好价光盘》—— 解析11/15 20:51（2）`。
当前文件：`人工核对表_20261103_11.3A｜Ps好价光盘_11152051(2).html`。

出价日期优先解析文件名前缀，其次标题；无年份使用解析时刻所属年份。Windows非法路径字符替换为下划线。文件写入拒绝覆盖；不同解析若同一分钟发生命名冲突，明确报错，不冒充同一解析的页面改版。

HTML内嵌review-metadata记录batch_id、content_hash、parsed_at及revision。格式改版必须显式传入revision_of，沿用解析时间并取该批次现有最高版号加一；识别内容不同则拒绝改版。重新解析不传revision_of，使用新的解析时刻及第1版。旧格式文件迁移需给出与原文件名一致的解析时刻，原文件保留并作为第1版基线。

## 4. HTML页面布局

- 独立UTF-8静态文件，夜间模式；背景`#111827`、正文`#e5e7eb`，表头底`#253343`，表格边框`#4b5563`。
- 内容宽度自适应，最大内容宽1800px并居中。宽度大于700px左右各100px；不大于700px左右各10px。
- BCD是A的子行：常规左缩进20px，窄屏8px。文首表头表采用相同缩进。
- HTML的8列固定百分比宽度：`18 / 32 / 10 / 10 / 7 / 6 / 6 / 11`，所有表共用`width:100%`与固定表格布局，竖线对齐，长内容允许换行。
- 表头仅一行，不增加解释数据行。表头与工具栏共同`sticky; top:0`，滚动时冻结悬浮。
- 表头及顶部全部按钮、开关、状态文字均13px，含彩色阶段标签；此规则覆盖此前12px表头及14px状态文字。

### ABCD条目

| 行 | 内容与样式 |
| --- | --- |
| A | 复选框＋数字序号`1.`＋完整原贴报价行；18px、字重600；每条递增，不使用括号编号 |
| B | 解析得原名、命中、main、type、平台、地区、价格、优惠方式；8列全部水平居中，16px |
| C | 问题详情，可选；合并8列、左对齐、16px，以`——`开头，支持多行 |
| D | `【命中情况】`及各阶段实际情况，16px；阶段名称单独14px加粗；之后留空再显示下一条 |

B行删除“问题简述”；全部问题去重后统一在C行逐项展示，不再按10字区分。无问题时不生成C行。main对应GPC的bangumi_main，即该GPC主游戏的Bangumi Subject ID；数字ID显示为链接，指向https://bgm.tv/subject/{id}，新标签页打开并带noopener noreferrer。缺失值仍为待确认，非数字内容仅转义显示、不生成链接；type对应GPC的type，以内容水平居中的灰化禁用下拉框展示，包含待确认及Base/rebase/Expansion/母子集/合集。main优先使用final的非空值，其次使用已命中目标保存的字段；type只读取final或带gpc_id的已命中GPC，且必须属于五种GPC类型。Bangumi的type=4是条目类别，不得作为GPC产品类型；无效值统一显示待确认，下拉选项不追加未知类型；final改选其他GPC/Subject时不沿用原目标字段。缺失字段显示待确认，不推断主版本ID或默认Base，不查询数据库、不改变审核载荷。

### D行阶段详情

别名库阶段明确未命中、后续阶段有确定目标时，追加“—— （拟增）A → B”。A为待写入game_alias.alias的识别名称，B为目标game_product_config.name_zh；候选无中文名时显示原名仅供建议，审核仍须确认最终中文名。两端使用低对比灰蓝code样式：背景#1b2939、字色#91a8be、圆角4px，无描边/阴影。此为拟新增预览，不表示已入库；别名已命中、歧义或无最终目标时不显示。


- 顺序：别名库、BGM 本地、BGM API、DeepSeek、GameFAQs。
- `【命中情况】`与首阶段同一行；整体对齐B第二列起始附近（当前CSS为子容器左侧20%＋10px）。
- D行实际命中阶段名称使用对应阶段背景色（别名绿、本地青、API蓝、DeepSeek紫、GameFAQs粉#FF6FAE），文字黑色；只着色名称，不着色分隔符。未命中、歧义阶段及整条无命中时保持原样。
- 阶段名称固定10em列内右对齐；不采用已撤回的两端分散对齐。`——`左右各保留一个半角空格，列间距0.25em。右侧描述及候选续行左对齐，不与名称或分隔符重叠。
- `未命中；无匹配候选`简化为`未命中`，`命中；唯一候选`简化为`命中`，`歧义；多个候选`简化为`歧义`。失败及其他有用原因不省略。
- 因前序唯一命中而未执行的后续阶段不显示；原日志、阶段证据仍保留跳过记录。其他未执行原因不能冒充已命中跳过。
- 实际执行阶段保留候选明细，内容与日志一致：名称、GPC ID（如有）、Subject ID（如有）；歧义必须列出所有该阶段候选，而非只显示最终选择。
- 每个候选单独`<code>`高亮：底`#26364b`、字`#f8d78b`、1px边框`#475569`、圆角5px，链接`#9bdbff`。与B行金色命中徽章区分，不需显示字面反引号。
- 不显示命中时间。历史结果优先从指定运行ID日志恢复各阶段证据；缺失时明确“未记录”，不得补造候选或阶段命中。

## 5. 页面交互

### 工具栏

- 左侧：`🧹 清除全部`、`⬜ 仅看未选`、`👁️ 显示全部`。
- 居中：`C行=问题详情`、`D行=命中详情`开关及`显示全部详情`按钮。
- 右侧：`↗️ 导出ALL未选`。
- `仅看未选`及C/D控制使用左右pingpong滑块：右绿为开启、左灰为关闭，`role=switch`与`aria-checked`和实际状态一致。原生按钮支持键盘操作。
- 清除全部只清除勾选，不删除条目；仅看未选隐藏已勾选项；显示全部恢复全部条目并关闭未选筛选；显示全部详情打开C/D。
- 状态格式`已勾选0/49项 · 显示全部`，随勾选和筛选变化。
- 当前状态仅保留在本页内存，刷新不保存；不自动确认条目、不调用导入。

### 紧凑模式

仅当C和D都关闭时自动启用：条目上/下间距10/12px、A底部间距5px；B上下padding各2px、行高1.25；金色徽章上下padding及margin归零、行高1.25。字号不变。打开任一详情恢复普通间距。

### 导出未选弹窗

- 导出的是全部未勾选条目，与页面当前是否显示、C/D是否关闭无关。
- 弹窗含大文本框（当前高55vh、字号16px，可编辑），底部左侧“复制全部内容”、中间`共48条`等数量、最后右侧“关闭”；复制反馈单独显示。
- 原序号保留，不对未选项重新编号。格式如下，条目之间空两行（即三个换行符）：

```text
序号. 原贴内容
B1——B2——B5——B6——B7——B8


下一条序号. 原贴内容
```

- 导出内容仍依次为原名、命中、平台、地区、价格、优惠方式，现对应B1/B2/B5/B6/B7/B8；不导出main/type，不重复B2。
- 仅导出文本中，B2的`/`左右空白去除，独立占位`-`改`_`：`- / - / - / 名称（ID）`变为`_/_/_/名称（ID）`；不更改名称内部字符及页面显示。
- Clipboard API优先，失败尝试选中文本复制回退；仍失败提示Ctrl+C，不虚报成功。无未选条目时文本为空、数量0。

## 6. 链接与文件安全

- 页面所有链接在新标签页打开；Subject链接带`target=_blank`及`rel=noopener noreferrer`，页面设置默认目标。
- 原文、候选名称、错误内容先HTML转义。候选高亮不意味着允许执行原文HTML或脚本。
- 不实现封面悬浮预览，此功能已由Karl取消。
- HTML保持原生表格、CSS和JS即可使用，不依赖远程图片、脚本或后台服务。

## 7. 最后确认的Markdown格式（独立保留）

HTML为ABCD，MD为ABC，不能将两者混为一套格式。

- A：`（1）原贴内容`，全角括号手动递增，避免被HTML小表格打断后有序列表重置为1。
- 文首一个仅单行的7列表头，不含序号列、不含第二行字段解释。
- B：保留原名、命中、平台、地区、价格、优惠方式、问题简述7字段，每个条目独立无表头小表格；MD的命中槽以`/`连接，Subject ID是链接，不要求HTML后续的金色与交互样式。
- C：仅问题超过10字时出现，合并7列、`——`开头，支持`<br>`换行；无问题填`-`，短问题仅填B。
- 使用MD内嵌HTML table/colgroup实现合并与固定列宽，宽度100%、固定布局，7列20/36/7/6/6/11/14%。普通Markdown管道表无法完整替代。
- MD不包含D行、复选框筛选、冻结工具栏或导出弹窗；不要求同步HTML字号和色彩。
- 最后一次重新解析对应的独立可读MD：`outputs/note-review/11.3_人工核对表_ab6619.md`；后续HTML视觉调整不追写历史MD。
- 对应原始审核载荷：`outputs/note-review/笔记审核_b28a0f.md`，保留原文、候选、`extracted`证据、`final`及`quote`。可读表不是入库载荷；人工确认后才按既有JSON契约导入。
- Typora可预览内嵌HTML；导出Word可能忽略HTML表格。需要保留视觉效果时优先HTML/PDF；原生DOCX生成是独立任务，不能宣称MD→Word可无损保留。
