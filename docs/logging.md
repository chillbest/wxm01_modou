# 日志使用说明

四个入口`python -m modou.parse_cli`、`modou.memory_cli`、`modou.bangumi_cli`、`modou.note_review`自动初始化日志，无需额外开关。继续使用原有参数。

## 文件与阅读

日志固定写入项目根目录`logs/modou.log`，UTF-8普通文本，可用记事本打开。每个文件最大10MiB，保留5份备份，名称为`modou.log.1`至`.5`；超过保留范围会自动轮转替换。日志同时写入标准错误，原有标准输出保持原用途。现有根目录debug.log不迁移、不删除。

每次运行生成run_id；job_id为入口模块。笔记条目带note_id（输入路径）、line（TXT实际行号；Bangumi JSON入口为条目序号）与raw_name。外部调用有request_id，导入事务有batch_id；没有对应上下文时字段为“-”。模块作为库直接调用时不自动创建文件，需要调用modou.logging_setup.setup()；条目上下文通过context()传递。

## 条目轨迹

每条记录本地别名、Bangumi本地资料、BangumiAPI及DeepSeek阶段的命中、未命中、歧义、调用失败或未执行。命中带候选名称和GPC/Subject编号；失败区分超时、HTTP状态码、网络失败、响应或处理异常类型，不记录异常原文。阶段未执行说明前序已命中、未启用AI或入口不支持该阶段。

条目最终状态为已识别、歧义或未识别，均仍待人工审核。已识别可来自唯一候选或AI候选选择，不能视为人工确认。每篇有数量汇总；若解析中途终止，以运行失败为准，不会伪造未执行条目的结果。无法识别的报价格式另记行号。

parse_cli和memory_cli只使用别名及可选AI名称建议，不执行Bangumi；note_review通过Bangumi识别时不重复记录初步解析器的空别名结果。

外部调用记录服务、请求ID、耗时及结果；Bangumi事件包含缓存读取，因此一次事件不一定代表一次网络请求。导入仅在事务退出成功后记录提交，异常记失败及回滚；提交前条目数量标为待提交。

## 安全与限制

不记录整篇笔记、提示词、响应正文、请求对象或原始异常。保留必要的条目名称、候选名称及本地路径。格式化阶段屏蔽URL、Bearer凭证、常见凭证赋值及当前环境中的密钥值，并转义换行防止伪造日志行。日志不是不可篡改的审计凭据。

使用标准库RotatingFileHandler，面向当前单进程CLI；避免多个进程同时写同一个日志文件，跨进程集中日志需另行实现。日志文件初始化失败会阻止命令开始，不静默丢失本次日志。

## 每文件3行摘要（2026-11-15，e5a19d63）

四个CLI的解析/review分支结束后输出以下摘要，上下各两行空白，import不输出。示例数值仅为格式说明：

```log
笔记统计｜《笔记.txt》｜开始2026-11-15 20:30:00｜成功｜总耗时45.32秒｜运行abc123
条目49｜已识别41｜歧义5｜未识别3｜未处理0｜全部待人工审核
耗时：读取/规则0.04秒｜本地查询16.68秒｜联网识别28.30秒｜输出0.30秒
```

开始时刻使用上海时区，耗时用单调时钟，四类互斥计时，不重复累计外部请求。单篇总耗时覆盖该篇处理作用域至输出完成；外围未单列的轻量组装计入读取/规则。批量开始时刻是该篇预读时刻，总耗时只累计该篇活动处理，排除共享准备及等待其他笔记的时间，首行标共享准备耗时另计；共享准备、批次汇总文件输出另有耗时事件。每篇输出阶段包含自己的JSON落盘和报告内容组装，批次报告最终落盘另计。

计数采用现有识别结果口径，互斥归类；失败保留已完成计数，剩余为未处理；读取失败等无法取得总数时显示未知。失败首行标失败阶段及安全原因，正常首行为成功，但仍需人工审核。Bangumi JSON入口以整个输入文件为统计单位。库调用可显式使用note_statistics启用摘要。
